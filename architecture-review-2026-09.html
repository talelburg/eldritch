Problem
Two parallel code paths each answer "which abilities fire here?". Of 41 commits to forced_triggers.rs, 34 also touched reaction_windows.rs. How a forced ability resolves depends on whether a sibling ability triggered at the same point. A lone forced hit takes resolve_one: it gets no event bindings and its usage limit isn't counted. Solution

Wins

  • silent drops become compile errors

  • coordinator stops scanning twice
  • #836-style drift can't recur

That changes behaviour, so it needs a ruling. The hot-spot pass also noted that the lone-vs-run split comes from reading the code and no test confirms it yet. 18's fire_at is how you'd write that test.

The reachability half: two answers to "which sources can I use?"

Problem
The engine's owner-aware routing is pub(in crate::engine), so the cards crate and the web client each write their own copy. The copies get Owner vs Controller wrong. Crypt Chill 01167 (verified at crypt_chill.rs:124) pushes the discarded asset onto the controller's discard. elimination.rs finds the owner through card.owner in one place and metadata.weakness in another. A native writes agenda_doom directly. instance_id == lookups appear 19 times. Separately, the reaction scan walks its own set of zones instead of using ADR 0010's reachability predicate.
Solution
One exported board module. It yields every ability source once for each trigger kind, finds any instance, and moves cards between zones, filing a leaving card by its owner. Every walker, card native and client lookup goes through it. The reaction arm becomes reachable_sources ∩ event scope.
Wins
  • the Owner / Controller rule lives in one place
  • a new Dunwich zone is one edit
  • the client can't drift from the engine
  • reactions and activations agree on reachability, so ADR 0010 actually holds
  • zone-move invariants tested in one module

This does not reopen ADR 0010. The reaction scan simply doesn't follow it yet ("One reachability predicate implements the bullets", for [free], [reaction] and [action] alike). That gap is latent: no card in the corpus prints a [reaction] on a location or a co-located card yet.

Gates: the Crypt Chill routing and widening the reaction scan to co-located sources are both rules calls for you. Lita Chantler's ruling for 01117 (arkhamdb.com/card/01117): "If Lita leaves play while a player controls her temporarily during "The Gathering" scenario (i.e. while she is technically not a part of that player's deck), remove her from the game (do not place her into any discard pile)." Crypt Chill can be drawn in The Gathering, so a Lita that Crypt Chill discards should leave the game.

Gates surfaced along the way

These are not refactors. Under CLAUDE.md's gate rules they need your decision. For this merge, the card text and rulings for 01165, 01167 and 01117 were read from the vendored snapshot and FAQ files. The rules-reference text has not been read for the rest.

Rules questions (gate 2)

  • Dissonant Voices 01165 vs hand Fast events. The card says "You cannot play assets or events." The hand-Fast scan never asks play_is_prohibited. This is verified and live (01). 01165 has no rulings (no-rulings.txt).
  • Crypt Chill 01167 → controller's discard (verified at crypt_chill.rs:124). The card says "choose and discard 1 asset you control". A Lita who left play this way should be removed from the game, per her ruling (05).
  • Reaction scan never reaches co-located sources (your location, an enemy there, a teammate's threat area), while activations do, via ADR 0010's predicate.
  • Usage limits on activated abilities are never enforced, and activation ignores eligibility (01).
  • "Each investigator" natives disagree on order and on skipping eliminated investigators. What's Going On?! may discard from an eliminated player's hand.
  • A forced ability alone vs with a sibling: only the ordered path counts usage limits and binds attacking_enemy / clue_discovery_count. Unifying the paths would also make forced abilities count usage limits (02).
  • Defeat checks read printed max health/sanity, not the modified value (ADR 0005). This is latent: no corpus card modifies them yet (10).

Code vs doc / ADR (gate 3)

  • Silent drops: forced_point returns None for DiscoverClues, DamageAssigned, DamagePlaced and EnteredPlay, and trigger_matches ends _ => false. Both contradict the "no silent no-op" standard.
  • card_registry.rs:113 says "Machete is the only consumer", but theyre_getting_out is registered there too.
  • architecture.md says the pipeline "consumes card-dsl" (it doesn't) and that handlers "reject cleanly on None" (most don't).
  • Native choices label options with Debug strings, against ADR 0011.
  • awaits_input and resolve_input disagree on 4 frame kinds.
  • The reaction scan bypasses ADR 0010's single reachability predicate.

Small cleanups, not ranked: queue_event always returns Done (folded into 18) · the Event doc comment is attached to TraumaKind · tombstone comments in game_state.rs · start_skill_test takes 10 args, and 5 of its 6 callers pass None, None · picker.rs:82 hardcodes the scenario · web/tests has no common/.
