# Phase plans

Eldritch is broken into 11 phases, milestone-tracked on GitHub. Each one's plan, status, decisions, and open questions lives in its own file in this directory. Closed phases get short retrospectives; the active phase has full detail; future phases capture what's been decided and what's still open.

## Why this exists

The plan-of-record for the project is GitHub (milestones, issues, labels). These docs sit on top: they capture **cross-issue context** that doesn't fit naturally in any single issue body — the *ordering* between issues in a phase, the *design decisions* made along the way that shape later work, the *open questions* the phase will need to settle.

When starting work on a new issue, read the relevant phase doc first. It's faster than re-deriving the context from chat history or git log.

## Cross-cutting / unmilestoned work

Some issues don't belong to a single phase. They live unmilestoned (mostly `p2-later`) and get picked up when convenient — the authoritative list is the [open unmilestoned issues query](https://github.com/talelburg/eldritch/issues?q=is%3Aissue+is%3Aopen+no%3Amilestone). Examples of the standing kind: `#31` (empty-`turn_order` guard), `#117` (event-keyed trigger index), `#119` (damage/horror dispatcher consolidation), `#174` (replay snapshots — build only when profiling demands it). The 2026-07-17 audit ([record](../audits/2026-07-17-audit.md)) filed a batch more (#564–#593, spanning engine/pipeline/server/web/infra).

The [Chapter 1 forward-compatibility gap register](../audits/2026-08-14-chapter-1-forward-compatibility.md) (#620, PR #621) is the other standing cross-cutting record, and unlike the audit it filed **no** issues — deliberately. It measures the DSL and engine against the whole Chapter 1 snapshot and sorts what it finds into four buckets; only the five bucket-4 entries ask for a decision, and each is written to become a decision ticket later rather than to be actioned now. Read it before any work that would widen the `CardRegistry`, the `GameState` partition, or the scenario-scoped action log. Its loose ends were three doc-drift items and a Rules Reference too old to answer Chapter 1 rules questions. The stale Rules Reference is **closed** (#624, PR #625): `data/rules-reference/rules/` now carries ArkhamDB's replica, which covers all of Chapter 1. The doc-drift items still have no issue.

The **2026-08-16 rules-conformance audits** (#626, PR #627) are the third standing cross-cutting record, and the first pass over the engine that could check it against the *printed* rules rather than against memory of them — five documents under `docs/audits/`, one per surface (skill tests; abilities and triggers; actions and phases; card play and zones; enemies and damage), 41 findings, each anchored to a verbatim quote from a named file under `data/rules-reference/rules/` and to a `file:line`. Unlike the register they **did** file issues: #628–#657. Three are decision tickets, each one missing abstraction wearing several hats — **#628** (no live modifier layer), **#629** (trigger dispatch and ability addressing), **#630** (automatic success/failure) — and each wants its own grilling session and an ADR before code moves. **#631** was the one `p0-blocker`: committed cards were stored as hand positions and the engine's own ST.2→ST.3 window could move them, a reachable panic with shipped Core cards — **closed** (PR #658), by giving committed cards the Rules Reference's own **limbo** state (`CONTEXT.md`) so they leave the hand at ST.2 and no hand index survives the commit. **#632** (enemies-and-damage, finding 1) is the first `p1-next` off the pile — **closed** (PR #659): a defeated enemy now goes to the encounter discard, or to its owner's discard pile if it is a weakness, so a defeated Ghoul Minion returns on the encounter-deck reshuffle and a defeated basic weakness stays in its bearer's campaign deck. Ownership is answered only for the unambiguous solo case; the bearer model itself stays with #654. **#633** (the same audit's finding 2) followed it — **closed** (PR #660): an enemy relocated by a card effect never ran the engage-on-arrival check, so agenda 01107 could walk a non-Hunter Ghoul onto the lone investigator and it would stand there ready and unengaged forever. Fixed structurally, with a `relocate_enemy` funnel every mover goes through rather than the one missing call. **#639** (the abilities-and-triggers audit, finding 2) is the next off the pile — **closed** (PR #666): the generic initiation gate ran on the play, reaction, and forced paths but never on `Trigger::Activated`, so First Aid 01019 spent an action and a supply healing an investigator with nothing to heal, and Old Book of Lore 01031 paid its exhaust to search an empty deck. The gate now sits in `check_activate_ability`, which the turn menu and fast-window enumerator both filter on, so the menu cannot offer an activation the validator would reject; `effect_can_change_state` gained the two arms whose no-op case is a property of the *target*, and target grounding filters ineligible investigators by the same predicate. A search is proven inert only against an empty deck — a fruitless *filter* still shuffles — and a filtered-to-empty candidate list at resolution **skips** its sub-effect rather than rejecting, so Medical Texts 01035 passing its test with nobody damaged does not unwind the chaos draw. The same rule one level down — a modal ability still offering a dead mode — is **#664**. **#638** (the actions-and-phases audit, finding 1) followed — **closed** (PR #667): Rules Reference p.10 Elimination *opens* with a step 0 the engine never implemented — *"For the purpose of resolving weakness cards, the game has ended for the eliminated investigator. Trigger any 'when the game ends' abilities on each weakness the eliminated investigator owns that is in play."* — so an eliminated Roland's Cover Up 01007 never dealt its mental trauma, in solo or in multiplayer. Step 0 needs a scan of its own rather than a narrowing of the existing `GameEnd` one, which skips non-`Active` investigators and fires every controlled card; and because a timing-point emit only *queues* (ADR 0003), the remaining steps ride a `Continuation::Elimination` frame so the abilities resolve while their cards are still in play. Elimination stays synchronous when no such weakness is in play, which is what keeps every other defeat's post-elimination bookkeeping unchanged. This **reverses** #567's acceptance criterion that a dead investigator's Cover Up must *not* fire, whose rationale read step 1 without the step 0 that exists to carve weaknesses out of it; #567's `RoundEnded` half stands. Resign will inherit step 0 for free once that action lands. **#637** (the same audit's finding 6) followed — **closed** (PR #668): the mulligan shuffled the rejected cards back into the deck *before* drawing their replacements, inverting the glossary's own order — *"These cards are set aside, and an equivalent number of cards are drawn and added to the player's starting hand. The set-aside cards are then shuffled back into the player's deck."* — so a card could be dealt straight back as its own replacement, which the rules forbid. The judgement call was where the step-8 weakness sweep over the redraw sits: **after** the set-aside cards return, which is both the glossary's ordering and the only one that leaves the sweep a deck to draw from — run while the mulliganed cards were still held out, a one-card deck emptied the hand outright. **#635** (the enemies-and-damage audit, finding 9) followed — **closed** (PR #671): `spawn: None` on an enemy conflated two different readings, and the engine could only act on one. One is the positive rule — *"If an enemy has no spawn instruction, it spawns engaged with the investigator who drew it."* — the other was an accident, the pipeline failing to resolve a printed Spawn clause and emitting `None` anyway. So Acolyte 01169's *"**Spawn** - Any empty location."* spawned it at the drawing investigator's location, the one location guaranteed **not** to be empty, and engaged them: a silent degradation into a *different, valid* rule, in an engine that otherwise refuses loudly on unmodelled content. `SpawnLocation` gained an `Unrepresented` variant carrying the clause, and the handler rejects on it. The scope taken was the minimum the issue allowed — the silent fallback stops; modelling the shapes (`Any empty location`, `Farthest location from you`, `Nearest [[Altered]] location`, …) and the spawning investigator's choice among multiple valid locations is **#670**. Two consequences are deliberate rather than incidental, and are recorded in the handler's doc comment: ten corpus enemies are undrawable until #670, because a rejection restores pristine state and the same draw re-rejects; and treating an unmodelled clause as the Rules Reference's *"it does not spawn, and is discarded instead"* was rejected, since discarding is itself a rule with an observable effect on the encounter deck. The refusal also raises the severity of **#575**, whose parser truncates Ruth Turner 01141's *"Spawn - St. Mary's Hospital."* at the first period, from *spawns in the wrong place* to *cannot spawn* — fixing it here was declined to keep it paired with #578 as the one spawn-*resolution* rework its triage asks for. **#628** (the skill-tests audit, finding 2) is the first of the three decision tickets to move: it had its `/grill-with-docs` session, and the result is **`docs/adr/0005-a-modified-quantity-is-recalculated-at-every-read.md`** plus a four-slice breakdown (#675, #676, #677, #674). The Rules Reference defines every modified quantity as a live recalculation — *"Any time a new modifier is applied (or removed), the entire quantity is recalculated from the start, considering the unmodified base value and all active modifiers."* — and the engine computed several of them once and stored the result. The design is one five-stage fold in RR's own order (base, row transform, additive, multiplicative, substitution), fed by two populations: modifiers *derived* from where cards sit, and modifiers *recorded* for lifetimes that outlive any card's zone. Two recommendations were reversed by a sweep over all 517 corpus cards, both in the direction of under-building — the multiplicative stage was believed speculative and has two consumers, and base-value replacement was not among the original findings yet has three. **#674**, the slice that needs none of the layer, went first — **closed** (PR #678): the engine summed the total, compared it and decided the verdict at ST.3, *before* the ST.4 chaos-symbol effects it pushed had resolved, under an in-code comment (*"The in-scope `immediate` effects (damage/horror) don't change the skill value"*) that the shipping corpus falsifies. `Appendix_II_Timing_and_Gameplay.md` orders ST.4 before ST.5, and ST.5 sums *"all active card abilities that are modifying the investigator's skill value"* — active **at ST.5**. In The Gathering a `[tablet]` deals 1 damage while a Ghoul is at your location; soak it onto a Beat Cop 01018 (*"You get +1 [combat]."*, printed health 2) already carrying 1 damage and the ally is discarded at ST.4, but the engine had banked its `+1` and a test that should fail by 1 passed. `Resolving` now performs ST.3 and ST.4 only, stashing the revealed token's resolution on the in-flight test; `DetermineOutcome` performs ST.5 and ST.6 off the board the symbol effects left behind. The token is still drawn exactly once, so a soak window suspending between the two steps resumes without re-drawing it. The one residual is deliberate and belongs to the later slices: the token's numeric modifier is still resolved to an integer at ST.3, so a `[skull]`'s −X-per-Ghoul would not notice a Ghoul removed at ST.4 — unreachable in the corpus, and ADR 0005 assigns expression-valued rows to the modifier layer proper. **#675**, slice 1a and the one carrying the run's risk, followed — **closed** (PR #680): `engine::modified_value` is now the single answer to "what is this quantity right now", keyed on a `ModifierTarget` (investigator / location / enemy / test) and a `ModifiedQuantity`, and it sweeps all six places a modifying card can sit — every investigator's controlled instances, every location and its attachments, every enemy and its attachments, and the current act and agenda — returning a **breakdown**, the base value plus each contribution attributed to its source, so a client can show why a combat value is 5. `constant_skill_modifier`, `unconditional_constant_stat_modifier`, `effective_shroud` and the skill-test handler's private summation are gone into it. The risk ADR 0005 flagged — reconstructing an evaluation context inside a read-only query — turned out to be smaller than feared: the only context a `ModifierScope` can ask about is which test is in flight, so a two-variant `ReadContext` (derivable from the state) covers it, and prey ranking passes `OutsideTest` explicitly to keep seeing only always-on modifiers. The scope the slice actually needed was **wider** than the ticket's letter, and in the same direction as #628's other two reversals: a `Modify`'s audience was implicit ("the controller"), which is exactly what made a non-controller modifier unreachable, so `Effect::Modify` gained a `ModifierAudience` — **`docs/adr/0006-a-modifier-declares-who-it-reaches.md`** — with `Stat::Fight` / `Stat::Evade` and an `Enemy::attachments` zone alongside it, without which three acceptance criteria are unobservable. Behaviour is unchanged: every corpus modifier is `Controller`-audienced except Obscuring Fog 01168, whose *"Attached location gets +2 shroud"* becomes `AttachedCard` and reads identically. Two residuals are deliberate. The clamp stays **last** — `sum_skill_value` returns the fold unclamped because the revealed token's ±N is still added after it, and `Modifiers.md`'s worked example turns on that ordering (*"base skill 4, –8 from chaos token, +2 from "Lucky!" for a total of –2, which is still treated as zero"*), so clamping inside the query would give 2. And a modifier gated on a predicate (`Effect::If` under `Trigger::Constant`) is still skipped, carrying forward a gap the superseded scan had; that is card *expressiveness* rather than read-time evaluation — everything the sweep matches is re-derived at every read — and closing it needs `Condition` variants no card can express yet plus a decision about who "you" is for a source with no controller, so it is **#679**. **#676**, slice 1b, followed — **closed** (PR #681): a modifier bought "for this skill test" attached to nothing in particular. A `ModifierScope::ThisSkillTest` modify was recorded against the investigator with no check that a test was running and no test identity, and the only thing that ever cleared it was that investigator's next skill-test teardown — so Hyperawareness 01034 (*"[fast] Spend 1 resource: You get +1 [intellect] for this skill test."*) activated at an open-turn menu with no test in flight silently banked a buff onto a test several actions, or rounds, later, and its ruling confirms nothing bounds the leak (<https://arkhamdb.com/card/01034>: *"You can use [fast] fast actions as many times as you want, as long as you can pay the cost; there is no limit."*). Skill tests now have an identity: `GameState` mints a monotonic `SkillTestId` at `start_skill_test`, stamped onto the in-flight test; a test-scoped modify records a `RecordedModifier` carrying `Lifetime::SkillTest(id)`; a row naming any other test is **inert** rather than merely drained; and the teardown expires rows by the ending test's id — on the ST.8 path and on the abandonment of a test whose tester was eliminated alike. This is also the ticket that introduced the **recorded** half of ADR 0005's modifier population, rows for lifetimes decoupled from any card's zone, and they store their delta as an *expression* evaluated at read time rather than a resolved integer, since Esoteric Formula 02254 (*"You get +2 [willpower] for this attack for each clue on the attacked enemy"*) makes freezing it at push time the same bug one level down. `ModifierScope` stays the card author's vocabulary in `card-dsl`; the evaluator's `Modify` arm is where it becomes a `Lifetime`, and therefore where a scope with nothing to stamp is refused. The scope taken was one step wider than the ticket's letter, and the PR argues it is obligatory rather than optional: once the modify rejects, #639's rule that the menu must not offer an activation the validator would refuse makes the initiation gate (`effect_can_change_state`) owe an arm for it, so Hyperawareness disappears from the turn menu outside a test instead of costing a resource and erroring. Two consequences: the end-to-end refusal is now the *gate's*, with the evaluator's own message covering the non-activation paths and unit-tested there; and `fast_play.rs`'s window-scope tests, which used Hyperawareness at a Mythos window with no test running, moved to Beat Cop 01018's *"[fast] Discard Beat Cop: Deal 1 damage to an enemy at your location."* so the gate they exist to test isn't masked by the new refusal. Three residuals are deliberate: `Lifetime` has one variant, because `ThisTurn` (#572) and until-end-of-phase (Encyclopedia 01042) still reject in the evaluator and so cannot be written down; the revealed token's ±N and the one-shot `test_modifier` stay integers, because the clamp must remain last and moving it inside the query is #677's; and a recorded row targets an investigator only, non-investigator targets arriving with #677's difficulty rows. It also closes **#571 §1** — #571 §2, the `step_native` idempotency tripwire, is unrelated and stays open. **#677**, slice 4 and the last of the four, followed — **closed** (PR #683): a skill test's difficulty was snapshotted at initiation and never re-read, so `glossary/Skill_Tests.md`'s *"While performing a skill test whose difficulty is modified based on another aspect of the game, that difficulty changes whenever the corresponding aspect's status does"* held nowhere. Two consequences. A location's shroud was modified by two mechanisms at two different times — Obscuring Fog 01168's *"Attached location gets +2 shroud."* folded into the snapshot at ST.1, Flashlight 01087's *"Your location gets -2 shroud for this investigation."* subtracted from it afterwards, with a clamp in between — and an enemy's fight and evade could not be modified at all, which is what made The Ritual Begins 01144, Cold Spring Glen 02244, Burned Ruins 02204, Horrors Unleashed 02239, Screeching Byakhee 01175, Avian Thrall 02094, Towering Beasts 02256 and Shadow-spawned 02142 unimplementable. `InFlightSkillTest.difficulty` and `test_modifier` are gone; the frame carries a `DifficultyBasis` — a printed number, a location's shroud, or an enemy's fight or evade — and `modified_value(ModifierTarget::Test, Difficulty)` resolves it and asks that target, so an enemy's modified fight value **is** the difficulty of a Fight action and every card that moves it moves the test. A `RecordedModifier` now names its own target, which is what lets Flashlight's reduction be a row over the *location* rather than a smaller snapshot; `Effect::Fight`'s combat modifier is the same shape over the controller's combat, and both travel as unevaluated `IntExpr`s so they are recalculated at every read. The card-facing DSL is untouched. Two consequences worth knowing. Mind over Matter 01036's carve-out (*"ignore any bonuses to Combat or Agility"*) stopped being a mechanism: the weapon bonus is a row over `Stat::Combat`, and an Intellect test never reads one. And `SkillTestStarted { difficulty }` is now the difficulty *as announced at ST.1*, which ST.6 re-reads — they agree for every in-corpus card, and `crates/web/src/store.rs`'s total reconstruction says so rather than claiming the old invariant. One gap is deliberate and filed rather than absorbed: an attack whose target leaves play between ST.1 and ST.6 reads a difficulty of 0 and automatically succeeds, reachable with Beat Cop 01018's fast ability at the ST.2→ST.3 window, and the vendored rules do not say what becomes of a test whose target leaves play — **#682** owns the ruling. With this in, **#628** can close. **#630** (automatic success/failure), the second of the three decision tickets, had its own `/grill-with-docs` session — the result is **`docs/adr/0007-a-tests-determination-is-resolved-above-the-fold.md`** and a four-ticket breakdown (#684, #685, #686, #687). ADR 0005 had placed automatic failure and success at stage 5 of the fold, as the substitution after the clamp; implementing it showed stage 5 cannot own the decision, because the two substitutions land on different quantities — *"If a skill test automatically fails, the investigator's total skill value for that test is considered 0. If a skill test automatically succeeds, the total difficulty of that test is considered 0."* — and a fold evaluating either cannot see the other's rows, so two independent stage-5 substitutions both yield 0 and compare as a **success**, which is the wrong answer. So a test's determination is a query over the recorded rows, resolved once for the whole test, which both quantity reads consult; and the ST.3/ST.4 skip falls out of asking that query *before* the token is drawn rather than after. The ticket's second stated requirement dissolved on inspection — there is no `EngineRecord` variant for a chaos-token draw, determinism comes from replaying the same actions against the same `RngState`, and a skip that is a pure function of game state reproduces identically. **#684**, the prefactor, went first — **closed** (PR #688): the revealed token's ±N and the investigator's elder-sign bonus were integers the driver added *after* the modified-value query returned, which is why the clamp happened in the driver and `ModifierBreakdown` still exposed an unclamped `raw_total()` as an escape hatch. Both are now recorded rows scoped by `Lifetime::SkillTest`, the committed cards' skill icons go into the breakdown rather than onto its result, and the whole ST.5 total — base, every additive row, the clamp — is one fold with the clamp genuinely last, so the escape hatch retires. The elder sign rides across as its `IntExpr` **copied unevaluated**: a recommendation to resolve it to a literal at reveal time was reversed by a sweep of all 106 investigators in the snapshot, twelve of which have a state-contingent modifier — and one of them, Roland Banks 01001 (*"[elder_sign] effect: +1 for each clue on your location."*), is Core, in the corpus, and the only elder sign with a card impl today, so freezing it would have pinned his clue count across the ST.4 window, reintroducing the exact staleness ADR 0005 exists to kill. No behaviour change: `crates/cards/tests/roland_elder_sign.rs` passes unedited, which is the criterion's own test of whether the move is right. The `[auto_fail]` token is deliberately untouched — it records no row and still substitutes the total from the driver — and becomes a determination in **#685**, at which point `InFlightSkillTest::token_resolution` has no reader left. **#685** followed — **closed** (PR #689): the `[auto_fail]` token stopped being a special case in the driver and became the mechanism. A skill test now carries a **determination** — automatically failed, automatically succeeded, or neither — stored as a `RecordedModifier` row scoped to the test, which is what buys `Lifetime::SkillTest`'s identity check, the ST.8 expiry sweep and the abandonment path with no new bookkeeping; `RecordedModifier` grows a `kind`, so a row is either a `Delta` (the additive pass) or a `Determination` (the fold's stage-5 substitution), and a determination targets the **test** rather than either quantity it substitutes. The precedence — automatic failure beats automatic success — is resolved by `test_determination` at **read** time, above the fold, so both rows may coexist and the answer does not depend on latch order. Both substitutions are the fold's last stage: an automatic failure substitutes the tester's total skill value to 0, an automatic success the test's total difficulty to 0, with the failure clause narrowed to the *tested* skill — *“the investigator's total skill value **for that test**”* — so a determined test does not zero a bystander's willpower. The contributions are kept underneath, so a substituted total still has a composition. The one judgement call is where the ticket's *“redundant ‘and also it wasn't an auto-fail’ term”* went: it is replaced by a match on the determination query rather than by a bare `margin >= 0`, because at **difficulty 0** — reachable via a printed `Fixed(0)`, or Flashlight 01087's *“-2 shroud”* on a shroud-2 location — an automatic failure gives 0 against 0, which a pure comparison passes. So the substitution is how the **margin** comes out right (0 against difficulty 3 fails *by 3*, which an “if you fail by 2 or more” clause needs to read), not how the outcome is decided. `FailureReason` keeps its two variants and gains no rules meaning; `AutoFail`'s doc-comment stops attributing the cause to a chaos token, since a card can now produce it with no token drawn. **#686** followed — **closed** (PR #690), and is the first player-visible slice: a card can say a test automatically fails or automatically succeeds, and it does. One new DSL primitive, `Effect::AutoResolve`, carries the two-valued determination — one variant rather than two with one consumer each, and deliberately not a job for `Effect::Native`, since automatic failure and success are Rules Reference concepts with their own glossary entry and the engine has to understand them whoever declares them. The evaluator's arm writes the same row the `[auto_fail]` token writes, so a card-latched determination inherits the identity check, the expiry sweep and the abandonment path without a line of new bookkeeping, and precedence stays resolved at read time — neither row suppresses the other, and the verdict does not depend on latch order. **No window machinery:** the moment comes from the declaring card's own trigger, exactly as `ModifierScope::ThisSkillTest` already works, so the engine enumerates no legal windows — the snapshot's latch range is wider than the rules' "before Step 3" skip clause, with Possession 03340 latching on commit at ST.2 and Delusory Evils 52065 reacting at ST.6. A determination with no test in flight **rejects**, for want of an identity to stamp, and `effect_can_change_state` gains the same gate so the turn menu never offers an activation that would only cost its price and error. `Event::SkillTestDeterminationLatched` names the determination and its source, because the event log is the client's only narrative channel and an automatic success would otherwise render as a win with a dash where the token would be and no stated cause; the `[auto_fail]` token deliberately emits **no** such event, its cause being already on the log as the `ChaosTokenRevealed`, at the accepted cost that a client cannot learn "this test is determined" from one event kind. One discrepancy surfaced and is recorded rather than absorbed: ADR 0007 says Possession 03340 latches on commit at ST.2, but this engine's `Trigger::OnCommit` fires at **ST.7** — deliberately, as a committed-card *consequence* rather than a commit-time moment — so a determination latched from it is written and expired correctly yet cannot change the test it was latched on, and a future Possession impl needs a commit-time trigger that does not exist yet. Nothing here is blocked by it; the any-trigger test uses an `OnPlay` `[fast]` event played at the test's player window instead, which is Stroke of Luck 02271's own shape. The chaos token is still drawn when the result is already known — rules-incorrect, and **#687**'s to fix. Each audit also carries a **Checked and found sound** section (read it before re-deriving that the engine is right about something) and an **Uncertain** section recording what the vendored sources genuinely do not settle, with a note on what would settle each — those are deliberately unticketed. One finding was a correction to the 2026-08-14 register rather than a divergence (#657).

### Tracker conventions (established 2026-07-17)

- **Milestone = phase deferral.** An issue milestoned to a later phase is deferred to it; an issue milestoned to the *current* phase is part of finishing that phase.
- **Priority labels order the current queue.** `p0-blocker` / `p1-next` / `p2-later` are load-bearing only on unmilestoned and current-phase issues — that's the knock-out order. On later-phase-milestoned issues, priority is merely intra-milestone ordering.
- **Cross-issue dependencies get a "Relationships" comment** on the issue (types: *Sibling* / *Blocked-by* / *Coordinate-with* / *Enables* / *Amplified-by*), so implementers see coupling without spelunking. GitHub's mention backlinks make one-sided comments discoverable from both ends, but prefer noting the edge on whichever issue an implementer is likely to pick up first.

## Template

Each phase doc follows this shape:

1. **Status** — closed / in progress / planned / architecture only, with a date stamp.
2. **Goal** — the milestone's one-liner.
3. **Issues** — every issue in the milestone, linked, with current state.
4. **Ordering** — Shape-B-style ordered plan, or "TBD" with rationale.
5. **Decisions made** — *closed phases only.* New design decisions go to `docs/adr/` instead; see "Maintaining these docs" below.
6. **Open questions** — what's not yet scoped. Also the **fog gauge**: a phase whose open questions are architectural and unresolved is a `/wayfinder` phase; one whose questions are only ordering and scope is a `/grill-with-docs` phase.
7. **Dependencies** — which prior phases this needs.
8. **What "done" looks like** — the concrete demonstration that closes the phase.

## Maintaining these docs

This section is the authoritative spec for the phase-doc update step of the PR procedure (CLAUDE.md step 6).

- **When a PR closing a phase issue is ready to merge — and ONLY then** (as the branch's final commit, after CI is green, so the entry reflects the actually-shipping state with the PR # known and review fixes folded in):
  - Move the closing issue's row to the phase doc's **Closed** table and bump any open/closed counts.
  - Flip the corresponding **Ordering / Arc** row to `✅ PR #N`.
  - Remove any **Open question** the PR settled.
  - **Do not add a "Decisions made" entry.** Design decisions live in `docs/adr/` now. If the PR made a choice that is (a) hard to reverse, (b) surprising without context, and (c) the result of a real trade-off, write it up as an ADR in the same commit. All three must hold — if a future PR-author would discover the same fact by grepping the code or reading a doc-comment / `TODO(#NNN)`, there's no ADR to write. Most PRs need none.
  - Existing **Decisions made** sections in closed phase docs stay where they are; they are not retro-migrated.
- **Never put phase-doc edits in earlier commits** of the same branch (churn + drift), and don't batch them into unrelated PRs.
- **When a phase milestone closes:** flip the phase's Status to ✅ (here and in the doc), trim Open Questions to closed-out items only, and the doc becomes a retrospective.
- **When the next phase starts:** flip its Status from ⏳/📐 to 🟡, add the ordered plan if not already there.
